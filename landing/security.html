Certification status

AEGIS is not yet SOC 2 certified. We are working toward it in stages and will publish each milestone here rather than claim it early:

StageWhat it meansStatus
1. Controls in placeTechnical controls implemented and documented (below).in place
2. Readiness assessmentGap analysis against the SOC 2 Trust Services Criteria (Security, Availability, Confidentiality) with a chosen auditor or compliance platform; policies written and adopted.next
3. SOC 2 Type IAuditor opinion that controls are suitably designed at a point in time.planned
4. SOC 2 Type IIAuditor opinion that controls operated effectively over an observation period (typically 3–12 months).planned

Until then, we can complete your security questionnaire, share our control documentation under NDA, and sign a DPA.

Controls in place today

  • Per-workspace API keys stored only as SHA-256 hashes; revocable; every request scoped to its workspace.
  • Git-provider tokens and customer-supplied model keys encrypted at rest (AES-256-GCM).
  • Agent-generated code runs in containerised sandboxes; remote sandbox failures fail closed.
  • Tamper-evident, HMAC-signed audit log, exportable as JSON or CSV with integrity verification.
  • Optional human approval gate before patches are applied.
  • Rate limits, quotas and spend caps per workspace.
  • Configurable retention, zero-retention mode and on-demand deletion — see the privacy policy.
  • Published subprocessor list with 30 days’ change notice.
