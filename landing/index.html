What it actually is

A REST API plus a worker pool — not a library

AEGIS is a Node.js (ESM, Node 20+) service: server.js accepts tasks, a BullMQ worker pool executes them. You run it, you don't import it.

Capabilities

What's actually implemented

No roadmap items on this list — every one of these ships in v2.0.0.

DAG-based planning

The planner LLM returns steps with depends_on; forward references are rejected and cycles are caught with Kahn's algorithm before anything runs.

Docker sandbox

Every lint and test run happens in a container. If Docker isn't available, the step hard-fails — no silent unsandboxed execution.

Git-based rollback

Each workflow gets its own worktree. Steps commit or roll back individually; a specific step can be rewound with dependents reset.

Multi-tenancy

Per-tenant API keys, quotas, and isolated worktrees and queues — concurrent workflows never step on each other.

Human-in-the-loop

Set CLAUDE_AUTONOMY=false to hold every patch for review, or flag individual steps with requiresApproval.

Vector memory

Hybrid cosine + BM25 + recency search over prior fixes, with per-tenant adaptive weighting. Degrades to a no-op without an embeddings key.

Dead letter queue

Exponential backoff retries, staleness sweeps, and webhook alerts once a step exceeds DLQ_MAX_RETRIES.

PR automation

Opens a pull or merge request after a workflow merges — GitHub, GitLab, or Bitbucket — targeting your configured branch.

Architecture

Every step is validated, sandboxed, and reversible

Agent inputs include AST-level repo context from repo-scanner.js and prior-fix context from vector-memory.js. Failures don't retry silently — they escalate through the DLQ.

Quickstart

Running in four commands

Redis Stack is required, not plain Redis — only FT.SEARCH gives the server and worker a shared vector index.

1
Clone and configure. Fill in ANTHROPIC_API_KEY at minimum.
2
Start Redis Stack. Plain Redis won't share the vector index across processes.
3
Run the server and workers. API server, agent worker, and DLQ worker are separate processes.
4
Submit a task. Poll the workflow until it reaches a terminal state.
terminal
# 1–2. clone, configure, start Redis Stack
git clone https://github.com/Naveenub/aegis.git
cd aegis && npm install
cp .env.example .env
docker run -d -p 6379:6379 redis/redis-stack-server:latest

# 3. server + workers (separate processes)
npm run server
npm run worker
npm run dlq-worker

# 4. submit a task
curl -X POST localhost:3000/task \
  -H "Authorization: Bearer $AEGIS_API_KEY_DEFAULT" \
  -d '{"task": "add input validation to login"}'
