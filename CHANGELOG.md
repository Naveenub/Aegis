# Changelog


## Unreleased

- **Model routing documented and configurable in deploy configs** — `agent-runner.js` already routed `planner` and `review-guard` to a cheap model (`AEGIS_MODEL_CHEAP`, default Haiku 4.5) and every other agent to a build model (`AEGIS_MODEL_BUILD`, default Sonnet 4), with a cost-cap fallback: when the build-tier reservation hits `SPEND_CAP_REACHED` / `CREDITS_EXHAUSTED`, the call is re-reserved once on the cheap model and flagged `capFallback` in token metadata (`AEGIS_CAP_FALLBACK=0` refuses instead). `TENANT_INACTIVE` / `GUARD_UNAVAILABLE` never fall back, and BYOK never downgrades. These were undocumented outside the source; `.env.example`, the k8s configmap and the README now list them. `AEGIS_MODEL` still pins both tiers.

- **FIX — `POST /billing/plan` was documented but not routed** — `engine/billing/plan-change.js` (free → paid, upgrade now, downgrade / cancel at period end) was implemented and unit-tested, but nothing in `server.js` called it, so the endpoint listed in the API reference and on the landing page returned 404 and no tenant could change tier. It is now registered with API key + `tenant.admin`, the rate limiter, and the billing gate (pending/suspended tenants use `/billing/portal`). `tests/billing-plan-route.test.js` pins the wiring.

- **Hard per-tenant LLM spend control, prepaid credits and BYOK** — `checkAllowance` stays informational (it only drives overage billing); enforcement now lives in `engine/billing/spend-guard.js`. Every platform-key call reserves its worst-case cost atomically (Redis Lua) before it is sent and settles to actual usage afterwards, so concurrent workers and step/planner retries cannot overshoot the cap, and an unreachable Redis refuses the call. Modes: `capped` (monthly UTC ceiling from `tiers.js` `spend.capUsd`, or a per-tenant override via `PUT /tenants/:id/spend`) and `prepaid` (credits topped up through Stripe Checkout, idempotent on the event id). Stripe-backed tenants are held to `AEGIS_UNVERIFIED_CAP_USD` (default $5) until their first paid invoice clears, and suspended tenants (failed payment) can no longer spend from an already-running workflow. Enterprise tenants can store their own Anthropic key (`PUT /tenants/:id/byok`, sealed with `AEGIS_TOKEN_ENCRYPTION_KEY`); BYOK calls skip the platform cap and token metering and never fall back to the platform key. Test dependency `ioredis-mock` is now declared (spend-guard and byok tests failed on a clean install without it).

- **SECURITY — sandbox stream transport for remote runners** — with `DOCKER_HOST` set, `sandbox.js` bind-mounted host paths that resolve on the *runner*, not the worker, so the isolated-runner path could not actually run a worktree. It now uses a `stream` transport (forced whenever `DOCKER_HOST` is set): the worktree (minus `.git`, which can hold remote tokens) is sent as a tar on stdin into uid-65534 tmpfs mounts, nothing is mounted, container writes never reach the host, `--pids-limit` is applied, and a timed-out run is removed on the runner. The dependency-install step's output is tarred back and rejected if it contains links or paths that escape. `AEGIS_SANDBOX_MODE=local`/`CI=true` remain ignored while `DOCKER_HOST` is set. `render.yaml` no longer relies on local execution. New env: `AEGIS_SANDBOX_TRANSPORT`, `AEGIS_SANDBOX_STREAM_MAX_MB`, `AEGIS_SANDBOX_WORKTREE_TMPFS_MB`. The sandbox image must contain the toolchain: stream runs preflight-check for eslint in the image and fail with build instructions if absent; compose builds `aegis-sandbox:local` in dind via a one-shot `sandbox-image` service the worker waits on. The container memory limit is raised by the worktree tmpfs size (tmpfs is charged to the cgroup). `npm run compliance:check` now also fails while `k8s/06a-sandbox.yaml` has privileged dind without a confirmed microVM `runtimeClassName`, or the configmap sandbox image is still a placeholder.

- **SSO, RBAC and user identity in the audit log** — (1) **Roles:** `viewer` (read-only), `member` (+ run/cancel/resume/rewind workflows, resolve reviews) and `admin` (+ API keys, users, audit log, BYOK, billing actions). API keys carry a role (`POST /tenants/:id/keys` takes `role`, default `member`); keys created before this release and env-var keys stay `admin`, so nothing changes until you issue narrower keys. (2) **OIDC single sign-on** per tenant (Okta, Entra ID, Google Workspace, Auth0, Keycloak…; authorization code + PKCE): operator configures it with `PUT /tenants/:id/sso` (`x-admin-key`), users sign in at `GET /auth/sso/:tenantId/login`, receive a short-lived revocable session token (`aegs_…`, accepted wherever an API key is) and are either pre-provisioned (`POST /tenants/:id/users`) or auto-created at a limited `jitRole` for allowed email domains. IdP client secrets are sealed with `AEGIS_TOKEN_ENCRYPTION_KEY`. Role changes and disabling a user take effect on the next request. (3) **Audit trail:** events now record `actorType: 'user'`, `actorEmail`, `actorRole` and `ip`; login, logout, denied logins, user and SSO changes are audited; keys remember who minted them (`createdBy`). The hash chain covers the new fields and existing chains still verify. New env: `AEGIS_DASHBOARD_URL`, `AEGIS_SESSION_TTL_HOURS`; `AEGIS_PUBLIC_URL` and `AEGIS_TOKEN_ENCRYPTION_KEY` are now also needed for SSO. New dependency: `jose`. The React dashboard gains an SSO login and shows the signed-in user and role. SAML is not supported (use an OIDC bridge).
- **Dashboard: audit log, user admin and role-aware UI** — the React dashboard gains an **Audit log** page (actor email/role or key, action, resource, IP; hash-chain verification status; CSV export) and a **Users** page (add users, change roles, disable) for admins. Controls the signed-in role cannot use (submit/resume/cancel/rewind, review resolution, key management) are now hidden instead of failing with 403, and nav links appear only for roles holding the permission.
- **SECURITY — auth was skipped on routes that used `requireApiKey` directly** — `requireApiKey` took four parameters, and Express treats any 4-argument handler as an error handler and never runs it for normal requests. Every route that passed it bare (`/tenants`, `/tenants/:id/keys`, `/tenants/:id/audit-log`, `/review-queue`, `/traces`, `/events`, `/anomalies`, `/workflows/:id`, repo routes, …) therefore ran with **no authentication**. Fixed by moving the optional tenant claim into a rest parameter (`fn.length === 3`); a test pins it. **If you ran a build with this bug, treat tenant API keys and BYOK/repo credentials as potentially exposed: rotate them, and review the audit log.** Note: per-tenant env-var keys (`AEGIS_API_KEY_{TENANT}`) only resolve on routes that pass a tenant claim, so they now fail on the formerly-bare routes — migrate them to runtime keys (`POST /tenants/:id/keys`).

- **Token metering split into input and output** — the single `tokens` meter summed input and output, but Claude costs $3/M in and $15/M out, so output-heavy tenants could run at negative margin. Now `tokens_in` / `tokens_out` are separate event types, Stripe meters (`aegis_tokens_in`, `aegis_tokens_out`), tier allowances (Starter 1.5M/300K, Pro 15M/3M) and prices (`STRIPE_PRICE_{TIER}_TOKENS_IN|OUT`, `OVERAGE_USD_TOKENS_IN|OUT`). `scripts/stripe-setup.js` refuses token overage below provider cost unless `ALLOW_BELOW_COST=1`. **Migration:** re-run `stripe-setup.js` (or add the new meters/prices by hand), update env/secrets, and move unreported legacy rows at the worst-case rate before the next flush: `UPDATE usage_events SET event_type='tokens_out' WHERE event_type='tokens' AND reported_at IS NULL;`

- **Clearer signup-disabled diagnostics** — `POST /signup` now returns a 503 that says why signup is off and what to set (`DOCKER_HOST`, `DOCKER_TLS_VERIFY`) instead of the generic "not available" text. On startup the server logs a warning when `DOCKER_HOST` is missing (always on Render, where it also blocks lint/test steps), so a missing runner shows in the logs rather than only as signup 503s.

- **Sandbox hardening for paid multi-tenant use** — the k8s `aegis-sandbox` Docker API is now mutual-TLS only (port 2376, `aegis-sandbox-server-tls` / `aegis-sandbox-client-tls` Secrets; see `k8s/README.md`), no longer plaintext 2375 behind a NetworkPolicy alone. Self-serve signup now requires an authenticated remote runner (`DOCKER_HOST` tcp:// + `DOCKER_TLS_VERIFY`, or ssh://); local mode, `CI=true`, unix sockets and the plaintext compose `dind` all refuse it unless `AEGIS_ALLOW_UNSANDBOXED_SIGNUP=true`. Docs and compose file now state the compose path is dev/single-tenant only. `provision-runner.sh certs` accepts `EXTRA_SANS`.

- **Per-tenant repos are the default in shipped deploy configs** — `docker-compose.yml`, `render.yaml` and `.env.example` now set `AEGIS_REPOS_BASE`; the global `AEGIS_REPO_ROOT` / `AEGIS_PR_TOKEN` / `AEGIS_PR_REPO` block is legacy-only and commented out. In multi-repo mode `runReviewPipeline` refuses to lint/test the server checkout when no tenant worktree is supplied.
- **Tenant base branch stays in sync with the default branch** — `aegis-tenant/<id>` was created from the default branch once and never updated, so upstream commits never reached new workflows and surfaced later as merge conflicts. The base branch now merges the default-branch tip before a new workflow branches from it and before each workflow merge (fast-forward when possible). A conflicting sync is aborted and leaves the base unchanged (logged, never blocks a workflow). Set `AEGIS_BASE_SYNC=off` to disable.
- **Disconnect clarifies GitHub App state** — `DELETE /tenants/:id/repo` now returns `200 { status, provider, note? }` instead of an empty `204`. For GitHub tenants the response says the App remains installed and that only the customer can uninstall it on GitHub.
- **GitLab and Bitbucket per-tenant auth** — in multi-repo mode (`AEGIS_REPOS_BASE`) a tenant can now connect a GitLab or Bitbucket Cloud repo, not just GitHub. `POST /tenants/:id/repo/connect` takes `{ "provider": "github" | "gitlab" | "bitbucket" }` (default `github`) and the browser returns to the new `/gitlab/callback` or `/bitbucket/callback`. Tokens come from OAuth 2.0, are stored AES-256-GCM encrypted (`AEGIS_TOKEN_ENCRYPTION_KEY`) and refreshed on demand under a lock (GitLab rotates refresh tokens). A revoked grant is detected at the next refresh and marks the repo `revoked`. Clone, push and PR/MR creation use the tenant's own credential; MR/PR creation now returns the already-open MR/PR instead of failing when the branch was pushed before. GitLab subgroups (`group/sub/project`) are supported. New env: `AEGIS_TOKEN_ENCRYPTION_KEY`, `AEGIS_PUBLIC_URL`, `AEGIS_GITLAB_OAUTH_CLIENT_ID/_SECRET`, `AEGIS_GITLAB_REDIRECT_URI`, `AEGIS_GITLAB_WEB_URL`, `AEGIS_BITBUCKET_OAUTH_CLIENT_ID/_SECRET`, `AEGIS_BITBUCKET_REDIRECT_URI`, `AEGIS_BITBUCKET_WEB_URL`.
- **Self-serve signup page** — `/get-started` (`landing/signup.html`) calls `POST /signup`, shows the API key once, and confirms the first payment with Stripe.js (Payment Element, including redirect-return handling). New `GET /signup/config` serves the publishable key from `STRIPE_PUBLISHABLE_KEY`. The server now serves the landing page at `/`, and the Starter/Pro pricing buttons link to the signup page instead of a mailto.

## v2.0.0

Major release. This snapshot summarizes AEGIS as it stands today — a Git-backed, DAG-driven multi-agent orchestration engine.

### Highlights

- **DAG-based planning** — LLM-produced JSON plans validated for cycles (Kahn's algorithm), forward references, and agent-name correctness before execution.
- **Seven specialized agents** — `feature-builder`, `debugger`, `refactorer`, `test-writer`, `security-editor`, `review-guard`, and `meta-reviewer` (retry fallback).
- **Docker-sandboxed execution** — every lint/test run happens in an isolated container by default; explicit opt-out only via `AEGIS_SANDBOX_MODE=local`, `AEGIS_SANDBOX_DISABLE=true`, or `CI=true`.
- **Git-based rollback and step rewind** — per-workflow worktrees/branches, `rollbackLastCommit`/`revertStepCommit`, rebase-and-retry merge strategy, and a `POST /steps/:stepId/rewind` endpoint with full audit trail.
- **Multi-tenancy** — per-tenant API keys, quotas, and isolated worktrees/queues.
- **Human-in-the-loop approvals** — `CLAUDE_AUTONOMY=false` or per-step `requiresApproval`, resolved via `/review-queue`.
- **Vector memory** — Redis Stack (FT.SEARCH) hybrid cosine + BM25 + recency reranking with per-tenant adaptive weights; degrades gracefully without `OPENAI_API_KEY`.
- **Dead letter queue** — exponential backoff, staleness sweeps, webhook alerts.
- **Anomaly detection** — success rate, p95 latency, latency spikes, and retry rate monitored on a fixed interval.
- **Metrics** — Prometheus text export (`/metrics`) and OTEL-compatible JSON (`/metrics/json`).
- **Inbound webhooks + PR/MR automation** — signature-verified GitHub/GitLab triggers; auto-opens PRs/MRs on `github`/`gitlab`/`bitbucket` after merge.
- **SSE dashboard and live event stream** (`/dashboard`, `/events`).
- **AST-based repo intelligence** via `acorn`-built symbol tables and import/call graphs.
- **CLI** (`cli/claude.js`) for submitting tasks and polling to completion.
- **Kubernetes manifests** under `k8s/` for namespace, Redis, PVC, server/worker/dlq-worker deployments, HPA, and ingress.

### Known limitations

- `npm run test:system` requires a live Docker daemon and Redis Stack; it won't run in sandboxed/CI environments without those.
- The local-HNSW vector memory fallback (plain Redis, no Stack) is single-process only and desyncs memory across a multi-container deployment. `initVectorIndex()` now fails fast with a descriptive error in that case unless `AEGIS_ALLOW_HNSW_FALLBACK=true` is explicitly set (single-process/dev only) — see `engine/vector-memory.js`.
